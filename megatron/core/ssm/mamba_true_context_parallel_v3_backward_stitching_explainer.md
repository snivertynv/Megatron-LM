# Mamba True Context-Parallel v3 Backward Stitching Explained

This document explains the one-all-gather True CP v3 backward designs in
introductory terms. It focuses on why the true boundary state gradient cannot
be computed locally, what the affine summaries mean, and how the convolution
halo gradient can still be reconstructed without a second collective.

The implemented full-prefix-replay prototype is summarized in the
[v3 control flow](mamba_true_context_parallel_v3_control_flow.md). This
explainer also retains the refined alternative, which uses the same adjoint
mathematics but factors the cross-segment convolution gradient into a
zero-terminal contribution and a terminal-state correction.

Assume convolution width `K = 4`, so the boundary prefix has
`S = K - 1 = 3` tokens.

## Implemented first version

The current CP-v3 code selects **full replay** as the first implementation.
It has the simpler ownership model and less work before the backward
all-gather, which keeps the collective launch off a longer pre-gather critical
path. During a grad-enabled forward it caches only:

```text
local segment input state S0       [2, B, H, P, N] FP32
selected predecessor raw halo      [2, 3, B, conv_dim] activation dtype
```

It does not cache `SL`, the globally gathered forward payload, or any
per-token state history. Backward communicates `log_alpha_body`, `gamma_body`,
raw prefix/tail xBC, prefix dt, and prefix `dpre` in one all-gather. It then
resolves all global adjoint boundaries and fully replays only the immediate
successor prefix needed for each local predecessor-tail gradient. The refined
`alpha_full/gamma_full/halo_zero` design below remains a possible optimization,
not the active implementation.

Both forward and backward replay are implemented as Triton kernels. In
particular, one backward program keeps a `[P,N]` adjoint tile resident while it
walks all global segments; Python does not loop over replayed tokens or
segments and no global convolved-prefix tensor is materialized.

## Glossary

| Term | Meaning |
| --- | --- |
| Segment | One contiguous global token window. Attention-style CP assigns two such windows to each rank. |
| `L` | Number of tokens in one segment. Its tokens are numbered `0` through `L-1`. |
| Prefix | The first `S=3` tokens of a segment: `0, 1, 2`. Their convolution needs raw inputs from the preceding segment. |
| Body | Tokens `3` through `L-1`. Their width-4 convolution depends only on raw inputs in the same segment. |
| State | Mamba's recurrent SSM state, with logical shape `[P, N]` per batch item and value head. |
| `dstate` | Gradient of the loss with respect to a recurrent state. It has the same logical `[P, N]` shape. |
| `lambda` or `lambda_L` | Mathematical shorthand for the true `dstate` leaving a segment. It is not a separate kind of tensor. |
| `alpha` | Multiplicative decay that transports a supplied terminal `dstate` backward through some tokens. |
| `gamma` | Additive input `dstate` generated by local output gradients when the externally supplied terminal `dstate` is zero. |
| Affine map | A map of the form `output = alpha * input + gamma`: a linear scaling plus an additive offset. |
| Halo | The three raw pre-convolution tokens borrowed from the preceding segment, or the gradient returned to those tokens. |

In the formulas below, `B` denotes batch size, `H` the number of value heads,
`G` the number of grouped `B/C` heads, `P` the value-head dimension, and `N`
the SSM state dimension. This document writes one segment at a time; the real
True CP layout adds a leading two-slot dimension for the two segments owned by
each rank.

## Segments and CP ownership

For `cp_size = 4`, the global sequence is divided into eight segments:

```text
global causal order

segment:   0     1     2     3     4     5     6     7
owner:    r0    r1    r2    r3    r3    r2    r1    r0
slot:      0     0     0     0     1     1     1     1
```

Thus rank 0 owns segments 0 and 7, rank 1 owns 1 and 6, and so on. The two
rank-local slots are recurrence segments, not a sequence that can generally be
concatenated and scanned locally. State passing first restores global segment
order.

Inside one segment:

```text
token:       0     1     2   |   3     4     5   ...   L-1
             \___________/       \_______________________/
                 prefix                       body
```

A width-4 causal convolution output is conceptually

```text
conv[t] = w0 * raw[t]
        + w1 * raw[t-1]
        + w2 * raw[t-2]
        + w3 * raw[t-3].
```

Here `w0` names the current-token coefficient. The v2/v3 tensor stores taps
in the opposite, oldest-to-newest order:

```text
w0 = conv_weight[:, 0, 3]
w1 = conv_weight[:, 0, 2]
w2 = conv_weight[:, 0, 1]
w3 = conv_weight[:, 0, 0].
```

This distinction matters when translating the symbolic halo equations below
into tensor indexing.

Outputs 0, 1, and 2 therefore read raw tokens from the preceding segment.
Output 3 reads local raw tokens 0 through 3, so every body convolution output
can be computed without a predecessor halo.

## Minimal recurrence model

For one batch item and value head, let `H[t]` be the `[P, N]` state after
token `t`. Using Mamba's `q=C`, `k=B`, and `v=x` convention, the conceptual
forward recurrence is

```text
a[t] = exp(A * dt[t])

H[t] = a[t] * H[t-1] + dt[t] * outer(x[t], B[t])
y[t] = H[t] @ C[t] + D * x[t].
```

Production code prepares `dt` by applying `dt_bias` and stable softplus in
FP32. It stores cumulative log decay rather than repeatedly multiplying
`a[t]`, but the equations above are the same recurrence.

After the Mamba output gate, the gradient entering the ungated SSM output is

```text
dpre[t] = grad_output[t] * z[t] * sigmoid(z[t]).
```

That output creates a local state-adjoint source

```text
r[t] = outer(dpre[t], C[t])       # logical shape [P, N].
```

A conceptual reverse step is then

```text
state_grad_at_t = lambda_from_future + r[t]
lambda_for_previous_token = a[t] * state_grad_at_t.
```

The actual kernels fuse this work and use compact decay tensors. The model is
useful because it exposes the affine dependence on `lambda_from_future`.

## Why the true terminal dstate is not locally available

Let

```text
lambda_L = dLoss / d(state leaving this segment)
lambda_0 = dLoss / d(state entering this segment).
```

It is useful to name all three forward-state boundaries explicitly:

```text
S0  -- prefix tokens 0,1,2 -->  S3  -- body tokens 3...L-1 -->  SL

dS0 <-- prefix backward ------  dS3 <-- body backward -------- dSL
```

Here `dSL` is `lambda_L`, `dS0` is `lambda_0`, and `dS3` is the
adjoint after the prefix and before the body. In backward, a supplied adjoint
moves from right to left. For the forward transition

```text
S[t+1] = a[t] * S[t] + injection[t],
```

the reverse transition is

```text
dS[t] = a[t] * dS[t+1] + local_output_source[t].
```

It multiplies by `a[t]`; it never divides by `a[t]`. Division would attempt
to invert the adjoint recurrence in the wrong direction and would be
numerically unsafe when the decay is small.

The subscript `L` denotes the boundary after the segment's `L` tokens. It does
not denote the loss. `lambda_L` contains contributions from every causally
later segment, so the owner cannot derive it from its local tokens.

What the owner can derive is a formula valid for any eventual `lambda_L`:

```text
lambda_0 = alpha_full * lambda_L + gamma_full.
```

This is an affine map. For example, a segment can know that its answer will be
`0.7 * x + 5` without knowing the future-supplied value `x`. It communicates
the coefficient and offset, not `x`.

## `alpha_body`: body terminal-dstate decay

The body contains tokens `3` through `L-1`. A terminal state gradient is
multiplied by every body decay while moving backward:

```text
alpha_body = product(a[t], t=3...L-1)
```

or, in the numerically stable representation used for communication,

```text
log_alpha_body = sum(A * dt[t], t=3...L-1)
alpha_body = exp(log_alpha_body).
```

`log_alpha_body` has logical shape `[B, H]` in FP32. Its scalar value for each
batch/head broadcasts over the `[P, N]` state matrix.

If the true terminal gradient were known, the part transported to the
prefix/body boundary would be

```text
alpha_body * lambda_L.
```

Before the all-gather, only `alpha_body` is known. The multiplication is
deferred until the reverse global scan resolves `lambda_L`.

For `L=3`, the body is empty, so its affine map is the identity:

```text
alpha_body = 1
gamma_body = 0.
```

## `gamma_body`: body output-driven dstate

`gamma_body` is the state gradient arriving at the prefix/body boundary due
only to output gradients inside this segment's body. It is defined by setting
the unknown external terminal gradient to zero:

```text
lambda_L = 0.
```

Conceptually:

```text
lam = 0

for t = L-1, L-2, ..., 3:
    state_grad_at_t = lam + outer(dpre[t], C[t])
    lam = a[t] * state_grad_at_t

gamma_body = lam
```

Consequently, for an arbitrary future-supplied terminal gradient,

```text
state gradient entering the prefix
    = alpha_body * lambda_L + gamma_body.
```

`gamma_body` has logical FP32 shape `[B, H, P, N]`. Calling it
"zero-terminal" does not mean that `gamma_body` is zero; it means only that
the external `lambda_L` was set to zero while computing the additive term.

`gamma_body` is required locally but is not part of the refined all-gather.
The segment owner uses it before communication to compute `gamma_full` and
`halo_zero`, then retains or recomputes it for its own normal local prefix
backward. A remote predecessor does not need `gamma_body`: its cross-segment
effect is already contained in the communicated `halo_zero`. Recovering it
from `gamma_full` would require subtracting `gamma_prefix` and dividing by
`alpha_prefix`, so the implementation must not use that reconstruction.

## `alpha_full`: full-segment terminal-dstate decay

The prefix decay is

```text
alpha_prefix = a[0] * a[1] * a[2].
```

The full segment decay is therefore

```text
alpha_full = alpha_prefix * alpha_body
           = product(a[t], t=0...L-1).
```

Production communication retains

```text
log_alpha_full = log_alpha_prefix + log_alpha_body
```

as FP32 `[B, H]`. `alpha_full` answers the following conditional question:

> If a terminal dstate is eventually supplied after token `L-1`, how much of
> it reaches the boundary before token 0 after passing through all tokens?

It depends only on the prepared forward decays, so it is locally computable
without knowing the terminal dstate itself.

## `gamma_full`: full-segment output-driven dstate

Let the prefix's reverse affine map be

```text
lambda_0 = alpha_prefix * lambda_3 + gamma_prefix,
```

where `lambda_3` is the gradient at the prefix/body boundary. The body map is

```text
lambda_3 = alpha_body * lambda_L + gamma_body.
```

Substitution gives

```text
lambda_0
    = alpha_prefix * (alpha_body * lambda_L + gamma_body)
      + gamma_prefix

    = (alpha_prefix * alpha_body) * lambda_L
      + (alpha_prefix * gamma_body + gamma_prefix).
```

Thus

```text
alpha_full = alpha_prefix * alpha_body
gamma_full = alpha_prefix * gamma_body + gamma_prefix

lambda_0 = alpha_full * lambda_L + gamma_full.
```

Equivalently, `gamma_full` can be obtained by reverse-replaying the complete
segment with `lambda_L=0`:

```text
lam = 0

for t = L-1, L-2, ..., 0:
    state_grad_at_t = lam + outer(dpre[t], C[t])
    lam = a[t] * state_grad_at_t

gamma_full = lam.
```

It is the zero-terminal input dstate generated by every local output gradient
in the segment. Its logical FP32 shape is `[B, H, P, N]`.

## The all-gather resolves the true dstates

Before communication, segment `j` knows only

```text
lambda_in[j] = alpha_full[j] * lambda_out[j] + gamma_full[j].
```

It does not know the true `lambda_out[j]`. The single all-gather distributes
the affine pair for every segment. Every rank then restores global causal
order and evaluates the chain backward:

```text
next_dstate = 0

for j = last_global_segment, ..., first_global_segment:
    true_terminal_dstate[j] = next_dstate
    next_dstate = alpha_full[j] * next_dstate + gamma_full[j]
```

For three segments this looks like:

```text
                      terminal sequence boundary
                                |
                                v
segment 2: lambda_out[2] = 0
           lambda_in [2] = gamma[2]
                                |
                                v
segment 1: lambda_out[1] = lambda_in[2]
           lambda_in [1] = alpha[1] * lambda_out[1] + gamma[1]
                                |
                                v
segment 0: lambda_out[0] = lambda_in[1]
           lambda_in [0] = alpha[0] * lambda_out[0] + gamma[0]
```

No rank computes a true boundary dstate from local tokens alone. After the
all-gather, each rank computes the same reverse scan locally from globally
gathered summaries and selects the terminal dstates for its two owned
segments. This local post-collective scan needs no second synchronization.

The all-gather therefore communicates neither a true `dS0` nor a true `dS3`
nor a true `dSL`. It communicates a conditional full-segment map. The prefix
has not been omitted: its affine effect has already been composed into
`alpha_full` and `gamma_full`, so the reverse global scan need not explicitly
replay three prefix tokens for every gathered segment.

## Why the convolution halo also depends on the future

The first three convolution outputs of successor segment `j` depend on the
last three raw inputs of predecessor segment `j-1`:

```text
predecessor segment j-1                 successor segment j

... [raw[-3], raw[-2], raw[-1]]  |  [raw[0], raw[1], raw[2], body...]
             \___________________________/
               cross-segment convolution
```

In backward, the successor prefix produces post-convolution gradients

```text
dQ = dC,  dK = dB,  dV = dx.
```

After SiLU backward and the transpose convolution, part of those gradients
must be added to the predecessor's final three raw `xBC` tokens. The true
prefix `dK/dV` depends on the successor's true terminal state gradient, which
is unavailable before the all-gather.

The key observation is linearity:

```text
true_halo[j]
    = halo_zero[j] + halo_terminal[j](true_terminal_dstate[j]).
```

## `halo_zero`: output-driven predecessor-tail gradient

`halo_zero[j]` is the predecessor-tail gradient generated by successor
segment `j` when its external terminal dstate is set to zero. The body still
generates `gamma_body`, so the prefix does not start with a zero adjoint:

```text
external terminal dstate = 0
body output gradients    -> gamma_body
prefix terminal seed     = gamma_body.
```

The successor owner has all inputs needed for this replay before the gather:

- actual prefix `dpre`;
- reconstructed prefix `x`, `B`, and `C`;
- cached prefix-entry forward state;
- prepared prefix decay;
- `gamma_body` from local body output gradients;
- convolution weights and preactivation values.

Conceptually:

```text
lam = gamma_body

for t = 2, 1, 0:
    state_grad_at_t = lam + outer(dpre[t], C[t])

    compute dC[t] from dpre[t] and the forward state
    compute dB[t] and dx[t] from state_grad_at_t
    add the direct D * dpre[t] contribution to dx[t]

    lam = a[t] * state_grad_at_t
```

Pack these post-convolution gradients as

```text
g_post[t] = packed(dV[t], dK[t], dQ[t])
```

and apply SiLU backward:

```text
g_pre[t] = g_post[t] * silu'(conv_preact[t]).
```

For the width-4 convention, the contribution to the predecessor's raw tail is

```text
halo_zero[-3] = w3 * g_pre[0]

halo_zero[-2] = w2 * g_pre[0]
              + w3 * g_pre[1]

halo_zero[-1] = w1 * g_pre[0]
              + w2 * g_pre[1]
              + w3 * g_pre[2].
```

`halo_zero` has logical shape `[3, B, conv_dim]`. It includes all local
output-driven contributions, including body output gradients transported by
`gamma_body`, but excludes the unknown external terminal-dstate contribution.
Only this cross-segment tail result is retained; ordinary local input and
parameter gradients remain owned by the later normal local backward.

In particular, the communicated `halo_zero` is not the successor's first
three `dV/dK/dQ` tensors. Those post-SiLU gradients are temporary inputs to
SiLU backward and the transpose convolution. `halo_zero` is the final
gradient for the predecessor's last three raw pre-convolution `xBC` tokens.
It contains both:

```text
the gamma_body-driven prefix dV/dK contribution
the actual prefix-dpre-driven dV/dK/dQ contribution.
```

Calling it the "zero-external-terminal-dstate halo" is more precise than
calling it a "gamma-body halo."

## Terminal-only halo correction

After the reverse global scan resolves the true terminal dstate, its
contribution at the successor's prefix/body boundary is

```text
terminal_prefix_seed = alpha_body * true_terminal_dstate.
```

The predecessor owner replays only this missing contribution through the
successor's three-token prefix, with local output gradient set to zero:

```text
lam = alpha_body * true_terminal_dstate

for t = 2, 1, 0:
    state_grad_at_t = lam                 # dpre[t] is zero
    compute terminal dB[t] and dx[t]
    terminal dC[t] = 0
    lam = a[t] * state_grad_at_t
```

The terminal correction has `dQ/dC=0` because `C` participates in producing
the local output and this replay has `dpre=0`. It can have nonzero `dK/dB` and
`dV/dx` because `B` and `x` participate in the recurrent state transition
through which the future dstate propagates.

The correction therefore needs only the successor prefix's prepared `dt`,
post-convolution `x` and `B`, and SiLU derivatives for the `x/B` channels. It
does not need prefix `dpre`, `C`, or the prefix-entry forward state.

The predecessor does not need the complete `dS3`. It rederives only the
missing terminal-dependent component:

```text
dS3_terminal = exp(log_alpha_body) * true_dSL.
```

The remaining component `gamma_body` has already contributed to
`halo_zero`. Starting with `dS3_terminal`, the terminal-only prefix replay is

```text
lam = dS3_terminal

for t = 2, 1, 0:
    # lam is the terminal-only adjoint of S[t+1].
    terminal_dx[t] = dt[t] * (lam @ B[t])
    terminal_dB[t] = dt[t] * (lam.T @ x[t])
    terminal_dC[t] = 0
    lam = exp(A * dt[t]) * lam
```

The shared `A` parameter and convolution weights are already present on each
CP rank. The all-gather supplies `log_alpha_body`, prefix `x/B`, prepared
prefix `dt`, and the prefix activation metadata needed by this replay.

After SiLU backward and the same tiny transpose convolution:

```text
true predecessor-tail gradient
    = gathered halo_zero
      + locally computed halo_terminal.
```

The first global segment has no predecessor, so its halo result is discarded.

## A small numerical illustration

Suppose a successor's output-driven prefix work produces

```text
halo_zero = [2.0, 1.0, -1.0]
```

and its terminal-only linear map happens to be

```text
halo_terminal(lambda_L) = lambda_L * [0.5, 0.3, 0.1].
```

If the reverse global scan later resolves `lambda_L = 4`, then

```text
halo_terminal = [2.0, 1.2, 0.4]

true_halo = halo_zero + halo_terminal
          = [4.0, 2.2, -0.6].
```

A full remote replay would wait for `lambda_L` and directly calculate
`[4.0, 2.2, -0.6]`. The refined design communicates the already available
`halo_zero`, calculates only the missing terminal correction after the scan,
and obtains the identical result.

## Combined backward payload

The exact packing can evolve with kernel implementation, but the refined
logical payload per segment is:

| Field | Logical shape | Purpose |
| --- | --- | --- |
| `log_alpha_full` | `[B, H]` | Resolve true global boundary dstates. |
| `gamma_full` | `[B, H, P, N]` | Zero-terminal additive term in the full segment adjoint map. |
| `log_alpha_body` | `[B, H]` | Transport the resolved terminal dstate to the prefix/body boundary. |
| `halo_zero` | `[3, B, conv_dim]` | Output-driven predecessor-tail gradient. |
| Prefix `x` | `[3, B, H, P]` | Form terminal-only `dB/dK`. |
| Prefix `B` | `[3, B, G, N]` | Form terminal-only `dx/dV`. |
| Prepared prefix `dt` | `[3, B, H]` | Replay the three prefix transitions. |
| Prefix SiLU derivative | `x/B` convolution channels | Map terminal `dV/dK` through the convolution activation. |

Affine state summaries and the combined communication buffer remain FP32.
Activation metadata may originate in the activation dtype before packing. The
implementation should preserve actual tensor strides in compute kernels and
avoid materializing folded sequence layouts.

The payload does not contain a true boundary dstate or completed prefix
`dQ/dK/dV`. Those values depend on the reverse global scan.

The "Prefix SiLU derivative" field is forward activation metadata, not a
gradient associated with `gamma_body`. If

```text
conv_post = silu(conv_preact),
```

then the field contains

```text
silu'(conv_preact)
    = sigmoid(conv_preact)
      * (1 + conv_preact * (1 - sigmoid(conv_preact))).
```

The terminal replay first produces post-SiLU `dV/dK`, multiplies them by this
Jacobian, and then applies the transpose convolution. Only the `x/B` channel
derivatives are needed because terminal-only `dQ/dC` is zero. A less
ambiguous field name would be `prefix_xB_conv_activation_jacobian`.

## End-to-end timeline

```text
BEFORE ALL-GATHER -- owner of each segment j
------------------------------------------------------------

Reconstruct local prefix/body forward values from saved inputs and halo.

Compute the conditional maps:
    lambda_in = alpha_full * unknown_lambda_L + gamma_full
    prefix_seed = alpha_body * unknown_lambda_L + gamma_body

Compute the known output-driven cross-boundary term:
    halo_zero

Package:
    log_alpha_full, gamma_full, log_alpha_body
    halo_zero
    three-token terminal-correction metadata

The true lambda_L is still unknown.


ONE COMBINED ALL-GATHER
------------------------------------------------------------

Every rank receives the summaries and boundary payload for every segment.


AFTER ALL-GATHER -- every rank
------------------------------------------------------------

Restore global segment order.
Reverse-scan (alpha_full, gamma_full).
Resolve the true terminal dstate for every segment.


AFTER THE SCAN -- owner of predecessor segment j-1
------------------------------------------------------------

Read successor j's gathered halo_zero and prefix metadata.
Compute halo_terminal from alpha_body[j] * true_lambda_L[j].
Add halo_zero + halo_terminal to predecessor j-1's final three raw tokens.


NORMAL LOCAL BACKWARD -- owner of segment j
------------------------------------------------------------

Seed body dK/dV with true_lambda_L[j].
Seed prefix dK/dV with
    alpha_body[j] * true_lambda_L[j] + gamma_body[j].

Compute all ordinary local input and parameter gradients.
Do not route the ordinary prefix halo a second time; the stitched path owns
that cross-segment predecessor-tail contribution.
```

## Full replay versus the refined factorization

Both designs use one all-gather and the same adjoint recurrence. They differ
in which work is completed before communication. The left-hand design is the
current implementation; the refined factorization is documented for a later
optimization experiment.

```text
FULL REMOTE PREFIX REPLAY

before gather                         after gather
-------------------------------       -------------------------------
send body affine summary              resolve true terminal dstate
send raw prefix/tail xBC      ---->    reconstruct successor prefix
send prefix dt and dpre                replay complete prefix backward
                                       produce complete halo gradient
```

```text
REFINED ZERO + TERMINAL FACTORIZATION

before gather                         after gather
-------------------------------       -------------------------------
compose full affine summary            resolve true terminal dstate
compute halo_zero locally     ---->    replay terminal-only correction
send x/B/dt/SiLU metadata              add halo_zero + correction
```

The refined design moves all work driven only by local `grad_output` to the
successor owner, where `dpre` and the cached forward prefix state already
exist. The predecessor later evaluates only the linear correction driven by
the resolved future dstate. That correction has no `dQ/dC`, which is why it
requires less remote metadata than a complete prefix replay.

### Communication volume

Let

```text
V = H * P                    # x/V channels
Kq = G * N                   # B/K channels; C/Q also has Kq channels
conv_dim = V + 2 * Kq
S = 3.
```

Ignoring the leading batch and two-slot dimensions, the full-replay payload
contains

```text
log_alpha_body                                      H
gamma_body                                          H*P*N
prefix and tail raw xBC                 2*S*(V+2*Kq)
prefix dt                                          S*H
prefix dpre                                        S*V.
```

The refined payload contains

```text
log_alpha_full + log_alpha_body                    2*H
gamma_full                                          H*P*N
halo_zero                                      S*(V+2*Kq)
prefix x/B                                      S*(V+Kq)
prefix x/B activation Jacobian                  S*(V+Kq)
prefix dt                                          S*H.
```

Excluding the `gamma` and `log_alpha` fields, both token-boundary metadata
totals reduce to

```text
S * (3*V + 4*Kq + H).
```

The refined design therefore communicates only one extra `[B,H]`
`log_alpha` field under the proposed FP32 packed policy. At
`H=128, P=64, G=8, N=128, S=3, B=1`, the difference is 128 FP32 values, or
512 bytes per segment, while the `gamma` tensor alone contains 1,048,576 FP32
values. Communication volume is effectively equal and dominated by `gamma`.

This comparison assumes backward does not retain the entire globally gathered
forward boundary payload. Retaining that payload could let the full-replay
design reuse raw prefix/tail `xBC` and `dt`, reducing backward communication
at the cost of additional training memory. The proposed boundary-cache policy
does not retain it.

### Compute and latency tradeoffs

The refined design would primarily be a compute-placement optimization, not a
bandwidth optimization:

- In the full-replay design, every rank reconstructs and reverse-replays the
  prefix of every global segment while resolving the adjoint chain. With
  `cp_size=C`, that is `2*C` explicit prefix replays per rank.
- In the refined design, each owner computes the full affine summary for its
  two local segments once. Every rank then scans the `2*C` gathered segments
  with one state-scale-and-add per segment.
- The post-gather halo work becomes a terminal-only `dV/dK` replay. It skips
  prefix `dQ/dC`, local-output state injection, and forward-state replay.
- Output-driven work is performed where local `dpre`, `C`, prefix states, and
  reconstructed convolution values already exist.
- The post-collective critical path is shorter and the benefit should grow
  with CP size because full prefix replays are no longer replicated across
  every rank.

The tradeoffs are that `gamma_full` and `halo_zero` must be ready before the
collective can launch, the ownership rules are more specialized, and the
terminal-only kernel must avoid double-counting the halo later produced by
normal local convolution backward. The full-replay design remains simpler and
is useful as a correctness oracle. End-to-end benefit must be measured because
the large communicated `gamma` tensor is unchanged.

## Does the zero-plus-terminal idea apply to forward?

The underlying affine decomposition also exists in forward, but it does not
remove forward prefix stitching under the one-all-gather constraint. The
forward analogue of

```text
dstate_in = alpha * dstate_out + gamma
```

is

```text
state_out = alpha * state_in + beta.
```

Here `beta` is the state produced when `state_in=0`, so it plays the same
algebraic role in forward that `gamma` plays in backward.

### The body already uses the forward decomposition

For body tokens `3...L-1`, the local relation is

```text
S_L = alpha_body * S_3 + beta_body.
```

Every body convolution output depends only on raw tokens from the same
segment. Each owner can therefore compute `alpha_body` and `beta_body` before
the forward all-gather. CP-v3 forward already communicates and applies this
body affine summary.

### The prefix summary is unavailable before the gather

The prefix also has a forward affine relation with respect to its incoming
state:

```text
S_3 = alpha_prefix * S_0 + beta_prefix.
```

If that relation were locally available, it could be composed with the body:

```text
alpha_full = alpha_body * alpha_prefix
beta_full  = alpha_body * beta_prefix + beta_body

S_L = alpha_full * S_0 + beta_full.
```

However, `beta_prefix` depends on the correctly convolved prefix `x` and `B`,
and prefix outputs depend on the correctly convolved `C`. Those convolution
values require the preceding segment's raw tail:

```text
prefix conv preact
    = local-prefix contribution
      + predecessor-tail contribution

prefix x/B/C
    = silu(prefix conv preact).
```

The segment owner does not have the predecessor tail before the forward
all-gather. It therefore cannot compute the true prefix `x/B/C`,
`alpha_prefix`, `beta_prefix`, or full-segment affine summary in time to place
them in that same collective.

### Why an additive zero-halo correction is not exact in forward

Backward can split the halo gradient because, after fixing the forward
activations, reverse-mode gradients are linear in the unknown terminal
adjoint:

```text
halo = halo_zero + halo_terminal(true_terminal_dstate).
```

The unknown forward halo instead passes through nonlinear and bilinear
operations:

```text
predecessor raw tail
    -> convolution addition
    -> SiLU
    -> x and B
    -> outer(x, B)
    -> recurrent-state injection.
```

In general,

```text
silu(local + remote) != silu(local) + silu(remote),
```

and `outer(x, B)` introduces cross terms. There is therefore no exact compact
forward decomposition of the form

```text
true prefix result = zero-halo result + independent halo correction
```

that can be evaluated before seeing the actual predecessor tail.

### Why computing full summaries would restore a barrier

An owner could compute the full forward affine summary if it first received
its predecessor halo, but that produces a two-collective flow:

```text
collective 1:
    exchange raw convolution halos

local work:
    reconstruct prefix x/B/C
    compute alpha_full and beta_full

collective 2:
    exchange full affine summaries.
```

That is the extra forward synchronization CP-v3 is intended to remove. The
current design instead gathers the body summary and raw boundary operands in
one collective. Afterward, every rank reconstructs preceding prefixes,
advances through each three-token prefix, and applies the corresponding body
summary.

### Possible after-gather forward optimization

After the one gather, every rank has enough raw boundary data to compute a
prefix affine summary. It could compute all gathered segments' prefix
summaries in parallel and then run an affine scan rather than serially
replaying prefixes while carrying the state. This would not reduce
communication or eliminate duplicated computation across ranks, and it would
materialize approximately

```text
[2 * cp_size, B, H, P, N]
```

of prefix `beta` summaries on every rank. The current replay carries one
state accumulator and avoids that global state-sized workspace. Parallel
after-gather summary construction is therefore a possible profile-driven
compute/workspace tradeoff, not the backward zero-plus-terminal optimization.

The forward/backward distinction is:

```text
forward body:
    affine summary is locally available and already used

forward prefix:
    affine coefficients depend on a remote raw halo and are unavailable
    before the one gather

backward prefix:
    saved or recomputed forward activations make the coefficients local,
    while the remaining unknown terminal dstate enters linearly.
```

The central invariant is therefore:

```text
Before communication:
    compute formulas and zero-terminal contributions, not true dstates.

After communication:
    resolve true dstates from the gathered affine chain.

Then:
    evaluate only the remaining terminal-dependent halo correction.
```
